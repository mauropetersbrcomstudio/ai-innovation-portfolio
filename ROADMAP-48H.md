# 48-Hour Portfolio Foundation Sprint

**Objective:** publish a coherent, professional portfolio foundation in 24–48 hours. This sprint does not promise that every future demo or client-specific case will be complete.

## Scope for the foundation
- [x] Central public GitHub repository with eight portfolio areas.
- [x] Two executable demonstrations in separate categories.
- [x] Automated Python test workflow in GitHub Actions.
- [ ] Responsive portfolio homepage and category navigation.
- [ ] Consistent project README/template and status conventions.
- [ ] Accurate root documentation and portfolio index.
- [ ] Verify public website deployment and links.

## Delivery sequence
1. **Foundation and presentation:** homepage, category navigation, project cards, status labels.
2. **Project standardization:** common README structure, setup/test instructions, architecture and limitations.
3. **Portfolio completeness:** category landing pages, demo-template starter, client-demo intake structure.
4. **Quality and publication:** verify links, run automated checks, review mobile layout, publish site where hosting settings permit.

## Acceptance criteria
- All eight areas are discoverable from the homepage.
- Existing demos are linked to their actual repository paths and accurately labelled.
- No fictional SME scenario is presented as a delivered client engagement.
- No unsupported metrics, testimonials, or business outcomes.
- Every executable demo has reproducible setup and test instructions.
- Deployment status is reported only after the public URL is reachable and verified.

## Out of scope for this sprint
- Completing every client-specific demo.
- Production integrations requiring credentials or paid services.
- Claims of production readiness without security, operational, and user validation.
